## 1. Audit slice

The P4 seams support the P5.1 admission checks without a schema migration:

| Seam | Finding | P5.1 use |
| --- | --- | --- |
| `ConversationBus.send()` | Persists the validated `Message` and `MESSAGE_SENT` marker inside the existing `BEGIN IMMEDIATE` store transaction. | Count blocking messages and check the limit before `save_model()`. |
| Delivery Tx1 | `run_ask()` stages `Run`, the `run_input` artifact, and `AGENT_RUN_STARTED`, then invokes its caller-supplied pre-provider hook inside the same transaction. | Check the turn budget after the at-most-once marker check and before writing `MESSAGE_DELIVERED`. |
| Delivery marker | `MESSAGE_DELIVERED` entries carry `room_id` and `task_id`, plus `message:<id>` and `run:<id>` references. | Count turns with a NULL-strict `(room_id, task_id)` query. |

The measured P4 baseline was `634 passed, 10 skipped` with one existing warning. No
schema version, persisted model, event vocabulary, task state, evidence, or
permission contract is changed by this slice.

## 2. Frozen decisions

### D-1 — Policy vocabulary is role-only

`PolicyPrincipal` is `AgentRole | PrincipalClass`, where `PrincipalClass` is
`HUMAN` or `RELAY`. Policy edges themselves contain only `AgentRole` values.
Direct logical-agent addressing derives `PARTICIPANT`; role addressing derives
the addressed role. A bare agent sender derives the role from the validated
authorship `Run`. `human:*` and `relay:*` identities derive their corresponding
principal classes.

### D-2 — Pair evaluation is pure and exact

`evaluate_edge(policy, envelope)` performs no I/O. Human/Relay traffic is
exempt from pair rules. `edges=None` means unrestricted role pairs for
pre-protocol compatibility. Otherwise the exact pair must exist, the exact
message type must be listed, and a blocking envelope requires
`blocking_allowed=True`. There are no wildcards, fallbacks, or silent
reroutes. System is never a policy-edge type.

### D-3 — Defaults preserve P4 compatibility

An absent `communication:` block, absent `budgets:`, or absent `edges:` uses:

```python
CommunicationBudgets(max_agent_turns=16, max_blocking_messages=3)
```

An explicitly empty `edges: []` is distinct from omitted edges and denies all
role-to-role pairs. This is a temporary pre-protocol compatibility choice;
P5.2 protocol stages must make their permitted edges explicit.

### D-4 — Configuration is strict and bounded

`communication.budgets` accepts integer limits from 1 through 1000 for agent
turns and 0 through 1000 for blocking messages. Edge roles must be existing
`AgentRole` values; types must be existing `MessageType` values other than
`system`; duplicate pairs and self-pairs are rejected; and `blocking: true`
requires one of `clarification_request`, `challenge`, `proposal`, or
`review_finding`.

### D-5 — Blocking accounting is message-ledger accounting

A blocking message is a persisted `Message` with `blocking=True` whose sender
does not begin with `human:`. The count is scoped by exact NULL-strict
`(room_id, task_id)` and is checked inside the existing bus transaction before
the insert. Relay-authored blocking messages count; human-authored blocking
messages do not.

### D-6 — Turn accounting is delivery-ledger accounting

One agent turn is one `MESSAGE_DELIVERED` binding marker in the exact scope.
The check is inside delivery Tx1, after the duplicate marker check and before
the new marker. `BEGIN IMMEDIATE` serializes independent connections, making
the admission and marker write one race-free spend. Re-entry on an existing
binding never checks or consumes another turn.

### D-7 — Reply admission happens before spend

`deliver_and_reply()` evaluates the prospective reply edge before fresh
delivery/provider I/O. Its sender is the delivery role and its recipient is
the parent sender's principal; the reply type is the resolved reply type and
replies are non-blocking. A previously bound delivery never spends another
turn. For a policy-enabled binding, only one exact
`reply-type:<value>` admission claim allows reply materialization to bypass
current edge re-evaluation; a standalone binding with no claim re-evaluates
the current reply edge.

### D-8 — Bound replies cannot be orphaned by policy drift

A bus reply is exempt from a second edge evaluation only when `reply_to_id`,
`run_id`, matching room/task scope, and a `MESSAGE_DELIVERED` marker carrying
exactly one `reply-type:<message.type>` claim alongside references to the
parent and run are present; the materialized reply must also be non-blocking.
Contradictory claims are refused. A standalone marker has no exemption and
uses the parent sender's persisted authorship role for policy evaluation.
Existing structural symmetry, authorship, and uniqueness checks remain in
force. Policy-disabled callers keep the original P4 marker shape.

### D-9 — Driver chain validation is fail-closed and pre-write

For each adjacent participant pair at hop `i >= 2`, the driver evaluates the
frozen forward shape `(previous principal -> current principal, NOTE,
blocking=False)`. A refusal is raised as `PolicyRefusal(SpecRefusal)` before
seed composition or persistence. Hop one is Relay-authored and therefore
exempt from role-pair rules.

### D-10 — Driver budget exhaustion is an honest stop

Before composing every forward or retry, the driver performs a read-only turn
precheck. The delivery Tx1 check remains authoritative for races. A budget
refusal becomes `StopReason.BUDGET_EXHAUSTED` with the typed refusal in
`ConversationResult.refusal`; it is never retried. If a race loses after a
forward has been composed, the undelivered row remains an honest ledger fact
and deterministic re-entry converges on the same identity.

### D-11 — P4 compatibility is additive

All three consumers accept an optional injected `CommunicationPolicyGate`.
`policy=None` leaves the P4 bus, delivery, and driver behavior unchanged.
Existing constructors, message models, event types, and structural ceilings
remain compatible.

### D-12 — Refusals are typed and transactional

The taxonomy is:

```text
CommunicationPolicyRefusal(MessageRejected)
├── EdgeNotPermitted
├── TypeNotPermitted
├── BlockingNotPermitted
└── BudgetExhausted
    ├── TurnBudgetExhausted
    └── BlockingBudgetExhausted
```

Bus and delivery admission refusals write no rows and invoke no agent. Driver
chain refusals write no rows. Budget stops after an already persisted seed or
failed attempt report the committed facts rather than pretending the whole
conversation rolled back.

## 3. Scope boundary

In scope:

- `relay/core/policy.py` with frozen models, pure evaluator, refusal taxonomy,
  SQLite ledger gate, and `policy_from_config()`.
- Strict `communication:` config models and `RelayConfig.communication`.
- Bus edge/blocking admission and delivery-bound reply recognition.
- Delivery prospective-reply admission and atomic turn-budget admission.
- Driver chain validation, per-hop admission, typed refusal result, and budget
  stop reason.
- Acceptance, concurrency, recovery, and architecture-boundary tests.
- README capability/roadmap status and this execution plan.

Out of scope:

- Protocols, stages, stage schedules, stage accounting keys, completion rules,
  moderator synthesis, decisions, loop heuristics, or discussion CLI.
- Broadcast, persistent rooms/seats, context reconstruction, token/USD/provider
  budgets, capability selection, escalation records, schema migrations, new
  event types, task states, roles, or changes to P4.4 identity derivation.
