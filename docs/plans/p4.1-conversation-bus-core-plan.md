## 2. Frozen decisions

| # | Decision |
|---|---|
| D1 | Vocabulary: add `clarification_request`, `clarification_response`, `proposal`, `note` (lowercase concept form per D.5). Frozen six + `system` untouched. |
| D2 | Additive `Message` fields: `blocking: bool = False`, `recipient_role: str \| None = None`. **No** `blocking_key` (P5). `references` remains **generic semantic references** (plans/decisions/findings/artifacts/evidence per D.5) — P4.1 freezes **no** reply-linkage representation; reply pairing representation (dedicated FK, references convention, or other) is P4.3's decision and v3 pre-empts nothing. Sole exception (marker bookkeeping, NOT reply linkage): the MESSAGE_SENT marker's own `references` carry `message:<id>` + room/task — existing EventType-marker pattern, unchanged. |
| D3 | Addressing (user-frozen): `recipient` always stores the **resolved logical-agent identity** that received the message; `recipient_role` stores the original role address when role-addressed. Direct: `recipient=<agent>`, `recipient_role=None`. Role: `recipient=<resolved agent>`, `recipient_role=<role>`. Not mutually exclusive. No string-prefix role encoding. Unresolved/ambiguous roles are **rejected before persistence**. Seat addressing: out of scope until P7. |
| D4 | Q-D resolved: non-agent senders enter only as `human:<name>` / `relay:<component>` (mirrors A.1 producer conventions). Bare senders = logical-agent identities. |
| D5 | Blocking validation: `note` can never be blocking; blocking flag legal only on `clarification_request`, `challenge`, `proposal`, `review_finding` (D.5 "blocker" row); blocking-ness is metadata, never implied by type. Type-level legality only — request/response pairing is P4.3. |
| D6 | `ConversationBus(store, writer, resolver)` — resolver is a local Protocol (`resolve_role`, `knows_agent`); fakes in tests, registry-backed resolver arrives P4.2. Role-addressed send with no/unresolvable/ambiguous resolver outcome ⇒ typed rejection, nothing persisted. |
| D7 | Marker discipline: MESSAGE_SENT marker content carries bounded metadata only (type, sender, resolved target, blocking) — **never** the conversation payload; references `message:<id>` + room/task (marker provenance per D2 exception). |
| D8 | Feed is a read-model: `relay/core/room_feed.py` composes chronological Room history from Message rows + EventLog rows (storage exposes raw scoped records only); MESSAGE_SENT markers excluded when the corresponding Message is represented (defensive fallback: render marker as a system entry if the Message row is absent); deterministic ordering with explicit stable tie-breaker (timestamp → kind-rank → id); pure read-only; no CLI rendering in this slice. |
| D9 | D.8 proof is dual: structural (AST test — `relay/core/bus.py` and `relay/core/room_feed.py` import neither `relay.core.state_machine`, `relay.core.evidence`, nor `relay.core.permissions`) + behavioral (traffic leaves task state, evidence, approvals, decisions byte-identical; `counts()` delta = exactly +1 message, +1 event per send). |
| D10 | Schema v3: `ALTER TABLE messages ADD COLUMN blocking INTEGER NOT NULL DEFAULT 0` + `ADD COLUMN recipient_role TEXT`; migration chain v1→v2→v3; v2 DBs upgrade in place preserving rows. |
| D11 | **`messages` joins the append-only enforcement family at BOTH layers:** (a) Python — `"messages"` added to `_APPEND_ONLY_TABLES` in `relay/storage/store.py` so `update_model`/`delete_model` raise `ImmutableHistoryError`; (b) DB — `messages_no_update` / `messages_no_delete` BEFORE UPDATE/DELETE `RAISE(ABORT)` triggers added via `_V3_STATEMENTS` (v1 is shipped history and is not retro-edited; fresh DBs traverse v1→v2→v3 and converge to the same schema; `CREATE TRIGGER IF NOT EXISTS` idempotent style). Rationale: §15 append-only canonical history — D.3/D.4 promotion produces NEW records; an editable message ledger would undermine promotion provenance and D.8. Consequence: `recipient`/`recipient_role`/`blocking` are final at insert (resolution precedes persistence — D3/D6). Pydantic-side `ConfigDict(frozen=True)` parity with `EvidenceRecord` is optional defense-in-depth, non-normative. |
| D12 | **Content bound (frozen value):** `MESSAGE_CONTENT_CAP_CHARS = 50_000`. Enforced at the bus boundary as typed rejection BEFORE persistence — no truncation, no silent capping (fail-closed house style). Applies to `Message.content` on `ConversationBus.send`; exactly-at-cap is accepted, cap+1 rejected. Deliberately NOT a DB CHECK constraint: the cap is a bus-contract rule and a tunable must not be frozen into schema; the store stays generic and the bus is the single public write path for conversation traffic (D9 keeps that honest). |
| D13 | **Broadcast denied outright in P4.1:** `recipient=None` without a role fails typed before persistence — every P4.1 message must carry a resolved recipient (direct or role-addressed). The `Message` model's field doc ("None means broadcast") stays unchanged: the denial is a bus-boundary rule (D12 precedent), no schema change. P5 may later permit broadcast under explicit communication policy. |
| D14 | **Self-send denied:** bare logical-agent `sender == resolved recipient` fails typed before persistence. Checked AFTER role resolution, so a role mapping back onto the sender is caught. `human:`/`relay:` senders are not logical-agent identities — the check does not apply to them. |
| D15 | **`MessageType.SYSTEM` reserved for `relay:*` senders:** agent or `human:*` senders may not author SYSTEM messages (typed rejection). One-directional: `relay:*` senders are not confined to SYSTEM. Bus-boundary rule; the model stays permissive. |

## 4. Acceptance gates

* **G1 Additivity + immutability:** v2→v3 migration preserves all rows; fresh DB lands at
  v3 with message triggers present; existing A.2/hygiene/architecture tests pass untouched.
  Append-only proof extends `TestAppendOnlyHistory` with `messages`: (a) Python API —
  `store.update_model(message_copy)` and `store.delete_model(message)` raise
  `ImmutableHistoryError`; (b) raw SQL — parametrized `UPDATE messages …` /
  `DELETE FROM messages …` raise `sqlite3.IntegrityError` matching "append-only";
  (c) rollback — a trigger abort inside an explicit transaction leaves the transaction
  consistent, ROLLBACK discards partial work, committed rows untouched (mirrors
  `test_transaction_rollback_preserves_append_only_tables`).
* **G2 Validation matrix:** every rejection case is typed and persists nothing — sender
  form (D4); role resolution (unresolved/ambiguous rejected pre-persistence; no resolver +
  `recipient_role` ⇒ typed rejection); broadcast denied outright (D13); self-send denied,
  direct and via role resolution (D14); `MessageType.SYSTEM` sender reservation (D15);
  broadcast + `recipient_role` illegal; scope (room and/or task required); blocking
  legality per D5 (incl. note-never-blocking); content bound per D12 (exactly-at-cap
  accepted, cap+1 rejected, nothing persisted); references shape (non-empty strings).
  **No** pairing cases — P4.3.
* **G3 Atomicity:** message + MESSAGE_SENT marker commit or roll back together.
* **G4 D.8:** structural + behavioral proof that conversation traffic cannot mutate
  canonical state (D9).
* **G5 Feed:** pure function of persisted records; MESSAGE_SENT dedupe; stable ordering
  under timestamp collisions; offline-testable; zero mutations.
* Full suite green, ruff clean.
