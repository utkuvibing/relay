# P7.4 — Room participant context reconstruction and honest session continuation

Status: implemented. Phase 7 is complete.

## Scope

App. D.10 / D.11-P7, closing the two deferred items from P7.3:

- **Context Engine reconstruction for each participant**: Room discussion
  recipients (`relay room ask`, `relay room decide`) receive a deterministic,
  bounded context block derived from canonical store records — ROLE · ROOM ·
  TASK · CURRENT PLAN · plan supersession chain · ACCEPTED DECISIONS ·
  UNRESOLVED BLOCKING COMMUNICATION · RELEVANT INTER-AGENT NOTES · CURRENT
  REVIEWER FINDINGS · RELEVANT ARTIFACTS/DIFFS · EVIDENCE · bounded Room
  history excerpts. The full transcript is never the input; excerpts are
  explicitly labeled non-authoritative.
- **Safe external-session continuation when supported, honest fresh-run
  otherwise** (App. C.2/C.4 seams, C.7 P7 honesty rule): harness agents
  declaring `session_resume` may resume a prior non-secret handle only under
  an explicit profile opt-in; anything unavailable, unsupported, expired,
  invalid, or unsafe falls back to a fresh backend run whose prompt says so.
  External session state — resumed or not — is never canonical.

Delivered:

- `relay/core/room_context.py`: pure read-only reconstruction
  (`build_room_participant_context` / `render_room_context` /
  `room_context_refs`), fail-soft (absent pieces render `(none)`; a corrupt
  plan chain renders an unavailable note instead of blocking delivery),
  deterministic ordering, per-section item caps plus a total budget of
  **8000 characters** (Python `len`, not UTF-8 bytes) enforced by
  priority-aware section fitting — the mandatory head (version line,
  ROOM, ROLE, TASK, CURRENT PLAN status) and tail (honesty footer +
  continuity marker) always survive, and under-budget sections degrade to
  explicit `…[N entries omitted — context cap]` / `(omitted — context
  cap)` notes rather than a mid-string slice. Rendered sections are
  task-relevant: accepted decisions are Room-global plus active-task only,
  CURRENT FINDINGS is the newest canonical review artifact's finding set
  per in-scope task (a newer clean review legitimately yields `(0)`), and
  every rendered evidence record contributes an `evidence:<id>`
  provenance ref (priority order: task → plan → decision → finding →
  evidence → artifact → message; deduped, capped at 32). Versioned
  `[relay:room-context relay.room.context.v1]` block plus a
  `[relay:continuity fresh|resume-rejected|resumed:<ref>]` honesty line;
- `HarnessAgentConfig.persist_session_ref: bool = False` (explicit C.4
  opt-in; default preserves pre-P7.4 persistence bytes);
- generic harness resume seam: `HarnessAgent.continuation_ref()` (default
  None), `HarnessAgent.resume_arguments()` (default typed refusal),
  `HarnessAgent.resume_argv_for(request)` consuming
  `AgentRequest.metadata["resume_session_ref"]` (empty by default —
  byte-identical behavior), and `HarnessAgent.resume_rejected(outcome)`
  (default False) — the adapter-owned positive identification that a
  failed run died on the resume ref, consulted only when a resume ref was
  actually sent;
- `relay/harness/errors.py`: `SessionResumeUnavailable` — the typed
  positive-rejection signal (subclass of `HarnessOutputError`). The
  runtime raises it only when a resume ref was sent AND the adapter's
  `resume_rejected` recognizes the session-invalid signature (nonzero
  exit or error envelope); arbitrary provider failures never carry this
  type;
- Claude Code / Antigravity adapters persist their parsed session id only
  under the opt-in, expose it via `continuation_ref()`, and declare
  `RESUME_REJECTED_SIGNATURES` for positive rejection detection; Codex
  declares no `SESSION_RESUME` and stays an honest fresh run by design;
- `latest_session_ref()` is **seat-scoped**, not agent-scoped: it scans
  delivery markers (`MESSAGE_DELIVERED` + `MESSAGE_DELIVERY_FALLBACK`) in
  reverse sequence and accepts a candidate only when the marker's
  `message:` ref resolves to a Message addressed to that seat
  (`recipient_role` + resolved `recipient`) and the bound Run's
  `agent`/`role` agree — one logical agent occupying two Room seats can
  never inherit the other seat's session;
- one-time fresh-run fallback: when a resumed delivery run fails with a
  `SessionResumeUnavailable` cause (`AskOutcome.cause` — typed, never
  text-matched), the same initiation continues exactly once on a fresh
  run prompted from the same canonical context. The fallback binds via a
  `MESSAGE_DELIVERY_FALLBACK` marker committed in its own Tx1
  (`message:` + `run:` + `prior_run:` refs); `deliveries_for_message`
  still sees exactly one `MESSAGE_DELIVERED` initiation (at-most-once
  untouched), reply materialization and crash recovery resolve through
  the fallback marker to the fallback run, and
  `relay/core/room_records._delivered_by` accepts both marker types so a
  fallback-authored reply keeps canonical provenance;
- `relay room ask` / `relay room decide` build the context block and the
  continuity decision per exchange, inspecting the SAME prepared delivery
  recipient (`recipient_for_inspection`) rather than a second constructed
  probe, and pass a primary `resumed:<ref>` suffix plus an honest
  `resume-rejected` fallback suffix through the existing `prompt_suffix`
  channel (the P6.4 appendix pattern — the frozen D15 envelope is
  untouched) alongside the decide contract.

Deferred (explicitly not P7 exit requirements): `relay why` (P8 decision
provenance), finding lifecycle/status, seat removal, and widening the
supersession quiescence boundary.

## Baseline

`origin/main` @ `2b99a6e` (post-P7.3, PR #34). Schema unchanged (no
migration — `runs.external_session_ref` already exists).

## Interfaces

- No new CLI commands. `relay room ask @role ... --by <human>` and
  `relay room decide @planner ... --by <human>` prompts now embed the
  reconstructed block outside the frozen envelope; behavior without prior
  sessions is an honest fresh run.
- Config: `harness.persist_session_ref: true` opts one harness profile into
  session-handle persistence (C.4 allowlist shape only; secret-shaped values
  never persist — adapters validate handle shape before returning it).
- Capability rule: only adapters declaring `session_resume` can resume;
  API-family recipients refuse a resume handle typed (they always run fresh
  from canonical records).

## Continuation honesty

Resume eligibility is the conjunction of: harness family, declared
`SESSION_RESUME`, profile opt-in, a prior persisted handle for THIS Room
seat (marker → message `recipient_role` provenance), and a handle that
survives the adapter's own `resume_arguments` shape check. Any conjunct
failing yields a fresh run whose prompt carries `[relay:continuity
fresh]` with the unavailable/unsupported/expired/unsafe rule stated. A
resumed run carries `resumed:<ref>` plus the canonical-store-supremacy
note, and its argv appends the adapter's resume flags after the grant
flags (authorization is never substituted). When a resume attempt is
POSITIVELY rejected by the harness (typed `SessionResumeUnavailable`
only — never arbitrary failure), the same initiation continues once on a
fresh run whose prompt carries `[relay:continuity resume-rejected]`; a
second rejection or any other failure surfaces honestly.
