# P7.3 — Room canonical plan/decision/finding graph

Status: implemented.

## Scope

App. D.3 / D.11-P7: *canonical plan/decision/finding relationships — frozen
plans, their supersedes chains, and decision graphs as first-class Room state*.

Delivered:

- **human plan freeze** (`relay room freeze`) that adopts a planner-authored
  discussion reply into canonical Room state and **binds execution**: the
  frozen plan is a Room/Task `PLAN` artifact, the durable build request is
  pinned, and the Room-scoped task lands at `IMPLEMENTING`, so
  `relay continue <task>` implements the frozen plan with **no planner stage**;
- **P6.4 records become Room history** for Room-bound tasks: the signal message,
  the promoted `Decision`, the revised `PLAN` and its `relay.plan_revision.v1`
  link all inherit the task's Room scope, and a `ROOM_PLAN_REVISED` marker makes
  the revision visible in the canonical feed;
- **explicit consequential exchange** (`relay room decide`): PROPOSAL →
  FINAL_POSITION with the strict `relay.room_decision.v1` contract, promoted by
  Relay into a canonical Room decision — ordinary `relay room ask` discussion is
  byte-identical and can never be frozen;
- **canonical findings**: one Room-scoped `Finding` per review finding of a
  Room-bound task, minted in the review's transaction and individually
  addressable so decisions can cite `finding:<id>`;
- **`relay room graph <room> [--json]`** plus canonical-record rendering in the
  Room feed.

Deferred: `relay why` (P8 decision provenance), finding lifecycle/status,
D.10 participant context reconstruction, external-session continuation, seat
removal, and widening the supersession quiescence boundary.

## Baseline

`origin/main` @ `c25d19e` (PR #32, P7.2 targeted room exchange). Schema v9.

## Interfaces

- `relay room freeze <room> --by <human> --from-message <reply>
  [--supersedes <plan-artifact-id>] [--title <text>]` — the freeze is the
  HUMAN's acceptance (App. D.3): a planner can never accept its own plan.
  Exit `0` on success, `1` on any refusal (zero store delta).
- `relay room decide <@planner> <question> --by <human> [--room <selector>]` —
  exit `0` when a canonical decision was promoted, `1` when the exchange
  completed without a valid `relay.room_decision.v1` reply (or on refusal),
  `2` on invalid usage.
- `relay room graph <room> [--json]` — human table + `relay.room.graph.v1`
  envelope; read-only and valid for closed Rooms; exit `1` on an integrity
  refusal.
- Room lookup and seat semantics are unchanged from P7.1/P7.2.

## Freeze source provenance (fail-closed)

The freeze source must be a **canonical planner discussion reply**:

- `reply.room_id == room.id`, `reply.reply_to_id` present, `reply.run_id`
  present, non-blocking, bare logical-agent sender;
- parent = `reply.reply_to_id`: same Room, `task_id is None`,
  `recipient_role == planner`, `parent.recipient == reply.sender`,
  `parent.type is clarification_request` and `reply.type is
  clarification_response` (so `relay room decide` output — `proposal` →
  `final_position` — is structurally ineligible);
- the reply is the **single canonical answer** to that parent;
- the authoring run exists, `run.agent == reply.sender`, `run.role == planner`,
  `SUCCEEDED`;
- a `MESSAGE_DELIVERED` marker authored by `relay:delivery` binds the parent
  request to that run inside the same Room.

No reply metadata is invented and no `Run.room_id` exists: Room membership is
proven by `freeze record → source reply → parent Room message →
MESSAGE_DELIVERED → run`.

## Freeze mint (one `BEGIN IMMEDIATE`)

Room-scoped `Task`; the frozen `PLAN` artifact (`room_id` + `task_id`,
`run_id` = source run); the `relay.room.plan_freeze.v1` record; workspace
context exactly as `_collect_context` represents it (task-scoped `REPORT`
artifact + `CONTEXT_COLLECTED` evidence); `PLAN_PRODUCED` evidence with the
`agent:<planner>` producer convention; the `relay.build.request.v1` record
(implementer = the Room's `@implementer` seat agent, model = the RESOLVED
implementer model, prompt = the human request or the plan text); the
`CREATED → CONTEXT_READY → PLAN_READY → IMPLEMENTING` transitions;
`Room.active_task_id`; and the canonical events, including the
`ROOM_PLAN_FROZEN` entry marker. Locked helpers (`_advance_locked`,
`_mint_context_locked`, `_persist_build_request_locked`) are reused so the
persisted shape matches a normal build boundary.

Refusals (all zero-delta): Room absent/closed; source missing / foreign / not a
canonical planner discussion reply; the source message is already frozen; no
`@implementer` seat; seat agent unknown, not harness-backed, or explicitly
granted below `workspace_write`; a supersession target that is missing,
foreign, not the current tip, or not at a quiescent position.

## Superseding freeze (quiescent boundary)

`--supersedes` mints `PLAN-(n+1)` plus its freeze edge on the SAME task and
moves the canonical tip. It is allowed only at a fail-closed quiescent
position derived from the ledger (`derive_position`): task at `IMPLEMENTING`,
no RUNNING build-owned/delivery/tool runs, no unresolved blocking signal, and
`next_action == "dispatch"`. Anything else refuses with `not_quiescent`
naming the blocking fact.

## Ledger + review acceptance

- `derive_position` accepts a plan root authored by a bound plan-stage run
  (P6.4) **or** named by a human freeze record for that task; exactly one root
  is still required, and chain edges may be P6.4 revisions or freeze records.
- `_validate_plan_freeze` re-derives the whole freeze chain independently
  (never trusting writers), including the `agent:<planner>` producer assertion
  on `PLAN_PRODUCED`; `_validate_plan_revision` is unchanged.
- `build_review_subject` (and its `verify_review_subject` /
  `verify_review_sources` / `build_fix_packet` callers) accept a Room-scoped
  planner run **only** when the plan artifact is named by a valid human freeze
  record for that task; everything else keeps `foreign_task` / `invalid_context`.

## Decisions (durable promotion)

`Decision` gains `source_reply_id` (durable promotion key), `references`
(validated in-Room citations) and `supersedes_decision_id` (canonical edge).
Schema v9 enforces one promoted decision per reply and at most one successor
per decision (partial unique indexes) and refuses self-supersession (triggers).

Promotion rules: only a newly ACCEPTED decision may supersede; the predecessor
must currently be ACCEPTED; a `reject` outcome forbids `supersedes_decision_id`
(payload invariant + promotion re-check); `accepted_by` is set only for
accepted decisions; a supersession flips the predecessor to `SUPERSEDED` and
records `DECISION_SUPERSEDED` in the same transaction; re-promotion of one
reply is a durable no-op. Invalid, unparseable or unresolvable output promotes
nothing while the exchange itself stays canonical conversation.

## Findings

A review of a Room-bound task mints one `Finding` per review finding in the
same transaction as the review artifacts (`advance_task(..., models=...)`),
deduped by `(review_artifact_id, source_finding_id)`, with one room-scoped
`FINDING_RECORDED` marker each. Standalone builds mint nothing.

## Room graph and feed

`build_room_graph` re-derives, from raw canonical records, ONE complete plan
chain per Room-bound task containing both edge kinds (human freezes and P6.4
revisions), Room decisions with promotion provenance and supersession edges,
and Room findings with their source review. It fails closed on a discontinuous
chain, orphan freeze records, non-human `frozen_by`, missing plan artifacts,
cycles, double supersession, decision supersession that contradicts the
canonical fields (including a `REJECTED` successor or a missing
`DECISION_SUPERSEDED` marker), a Room-scoped decision without
`source_reply_id`, unresolvable/foreign references, and findings naming a
foreign review or task.

The canonical feed renders each Room-scoped record exactly once at its entry
marker (`ROOM_PLAN_FROZEN`, `ROOM_PLAN_REVISED`, `DECISION_ACCEPTED|REJECTED`,
`FINDING_RECORDED`) with bounded text, and renders `DECISION_SUPERSEDED` as a
later transition entry. A promotion entry keeps rendering the state carried by
its own marker even after the row is superseded. Record-free Rooms render
byte-identically to pre-P7.3.

## Room-bound signal routing

`_signal_services(..., task=...)` resolves roles through the **persisted Room
seat snapshot** for Room-bound tasks (P7.1 semantics: rebound seats are
respected, and a persisted seat whose agent is no longer configured fails
honestly at delivery — never a silent fallback to the config role binding).
The config agent set only widens the bus's bare-sender membership check, and
the agent factory keeps using current `relay.yaml`. Standalone builds keep the
config resolver byte-identically.

A closed Room parks the micro-exchange: `ClosedRoomError` is handled at the
signal send and delivery boundaries and converted into the existing durable
`relay.build.escalation.v1` observation with reason `room_closed` (the task
parks `COMMUNICATION_BLOCKED`). Nothing partial is persisted — no signal
Message, no marker, no Run — and after `relay room resume` the next
`relay continue` retries the same logical continuation normally. The OPEN
fence is never bypassed.
